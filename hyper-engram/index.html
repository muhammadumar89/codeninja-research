§00The thesis

Every operation has something to teach its AI. The first question we ask is what belongs in context and what belongs in the weights. We train both.

Hyper Engram is the agentic memory of the Hyper stack. It is the loop that trains a system run after run: every run, outcome and correction is written back, compressed into versioned principles every morning, and reinflated by the model into the next problem it meets. A lesson learned today changes tomorrow's behaviour.

§01The learning loop

A system that improves itself, one loop at a time.

One master agent runs each RSI Loop. Two routines learn on their own every morning. None of them speak to each other directly: they read and write one memory, and that memory is what the planner reasons over.

§02Platform

Four stages. One training loop.

Data, training, evaluation and serving, rebuilt for systems that work in the real world: capture, compression, reinterpretation and reinflation. The training signal lands where the model reads it, so a lesson is in use the next morning.

01

Capture

Every run is training data. Every run is kept as an episode: what it did, what it measured, and what went wrong with how it worked. Nothing is thrown away.

02

Compress

Distillation, every morning. Every morning a routine distils raw learnings into versioned principles. Many observations become one. Contradictions are resolved. What never mattered fades.

03

Reinterpret

A second reader, every time. A later reader, usually the master agent, finds what a run missed and writes a rule for next time onto that run's own episode. An adversarial verifier checks every writer.

04

Reinflate

Context at inference. When a new problem arrives the model reads the compressed memory and expands it into this place, these laws, these people. The same lesson becomes a different design each time.

§03Reinterpretation

Learned tonight. Used tomorrow morning.

Every routine begins its run by reading the feedback and gap records on its newest episodes, before it does anything else. That intake is the whole trick: behaviour changes without anyone touching the code.

  1. Day 1

    A run misses something

    A design senses the warning a real incident would have started with, and never says who must act on it.

  2. Evening

    A later reader finds it

    The master agent reads the run and files a gap record on its episode: what was missed, the fix, and a rule for next time, written in the routine's own terms.

  3. Day 2, first thing

    The routine reads before it acts

    Its intake lists every rule in force. The rule is now part of how it works, with no change to its code.

  4. Next loop

    The record closes, or it does not

    The next RSI Loop checks whether the gap closed. A record still open is the first item of the next plan.

§07Laws

Eight rules no loop may break.

They hold across every phase and every agent. A change that would bend one stops and waits for a person.

01

Every lesson in its place

Each lesson is trained where it does the most good: into the context the model reads, or into the weights when a skill is stable and used at volume.

02

Meaning, never keywords

Any decision about what a sentence means is put to a model and stored. Keyword scoring is banned.

03

Every claim stands on a source

An entry needs a dated source. A principle needs the learnings it was distilled from.

04

Evaluation stays blind

Held out tasks are never shown to the planner. Incident cases never feed the memory.

05

Two agents, two views

Every writer has an adversarial verifier. Nothing verifies its own output.

06

The record is the context

Commits, episodes and gap records carry the why. A session that lost its memory reads the log first.

07

Every release is reversible

Each RSI Loop is tagged. A bad change is reverted by its own commit, a bad principle by its own version.

08

The memory is yours

It lives in your perimeter, on models you host, and it survives every model you replace.

§09In depth

Questions about Hyper Engram

What is Hyper Engram?

Hyper Engram is the agentic memory of CodeNinja's Hyper stack. It keeps every run, outcome and correction, compresses them into versioned principles, and gives them back to the model as context when it reasons. It is the loop that trains Praxis and Hyper Pragma, run after run.

How does Hyper Engram train a system?

Runs are captured as episodes, daily routines compress them into principles that cite their sources, later readers file what a run missed as rules for next time, and at inference the model reinterprets the compressed memory for the problem in front of it.

What is compression and reinflation?

Compression turns many observations into one small principle, resolving contradictions and dropping what never mattered. Reinflation is the model expanding that principle into a new situation: a different country, operation or set of people. The idea follows Michael Levin's work on self improvising memory in living systems.

Do you also train model weights?

Yes, where it pays. On every engagement we first decide how much of what the system must learn belongs in context and how much in the weights. Engram trains the context side every day; stable skills used at high volume are trained into the weights of models the customer hosts.

What happens when a better model is released?

It is swapped in. What Engram holds is not stored in the model, so it carries over and the new model starts with everything the system learned in context.

Where does the memory live?

Inside the customer's perimeter, on their infrastructure, under their control, including air gapped deployments on models they host themselves.
